# Идеи на будущее (вне текущего скоупа)

Этот файл — "parking lot" для идей, которые не являются частью
заявленной цели проекта (демонстрация Go-скиллов через Kanban-доску с
real-time синхронизацией). Хранятся отдельно от `vision.md`, чтобы
не создавать впечатление, будто это часть плана MVP или Фазы 2, и не
провоцировать скоуп-крип.

Если какая-то из идей будет решено делать — сначала переносится в
`vision.md`/`roadmap.md` с собственным этапом и, при необходимости,
ADR.

## Модуль сбора и классификации вакансий

- Импорт вакансии по ссылке — парсинг страницы, извлечение данных
- AI-классификация вакансии (в первую очередь — интеграция с внешним
  LLM API через HTTP-клиент с таймаутами/retry/circuit-breaker; сам
  факт использования AI вторичен, интереснее для демонстрации именно
  устойчивый клиент к нестабильному внешнему сервису)
- Автосоздание карточки на доске из импортированной вакансии
- Domain-сущность `Vacancy` — модель данных не решена: либо расширение
  `Card` через опциональный `metadata jsonb`, либо отдельная сущность,
  генерирующая `Card`. Решается при переносе идеи в vision.md/roadmap.md,
  не раньше — сейчас это открытый вопрос, а не архитектурное решение

Потенциально может опираться на worker pool из Этапа 5 (roadmap.md),
если тот будет реализован раньше — но стоит помнить, что парсинг
внешних страниц/вызов LLM API, в отличие от примера с email-уведомлением
в Этапе 5, это I/O-bound задача с вероятными внешними сбоями: понадобятся
таймауты, rate-limiting и retry, не только сам факт очереди задач.
